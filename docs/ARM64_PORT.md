# ARM64 独立版本：实现与核验

更新：2026-10-28。新项目目录：`D:\C\C_Code\compiler-arm64`。从 `D:\C\C_Code\compiler` 复用已审计实现，并将后端切换为 AArch64。RISC-V 项目仍在原目录；ARM 项目独立构建、测试和打包，不依赖相邻项目的源文件或二进制。

## 参赛目标

依据仓库中《2026 年全国大学生计算机系统能力大赛—编译系统实现赛道技术方案》第一、七页，第五及第二十六条：ARM 目标为 **ARMv8-A 64 位 / Cortex-A53**，目标环境 Ubuntu22.04，GCC11.2 负责汇编和链接，命令行仍为 `compiler testcase.sysy -S -o testcase.s`，性能测试追加 `-O1`。宿主继续为 Ubuntu24.04/AMD64、Clang18、C++17、O2、lm。

本地使用 AArch64 GCC11.5 与 QEMU，ABI 专项指定 `-cpu cortex-a53`；版本补丁号不同于官方11.2，尚无目标板或平台实际提交成绩。源语言、Tensor、IR/SSA 和中端方案沿用原要求；没有引入 LLVM/GCC 编译器源码或框架库。

## 复用与改动

- 前端 Lexer/Parser/AST/语义构建、Tensor 降低与内存管理原样复用。
- Type/Value/User/Use、Module/Function/BasicBlock/Instruction、Verifier、强类型 IR 文本、三层表示与 flags 原样复用；指针宽度继续为64位。
- CHK 支配分析、DF/IDF、Mem2Reg、Phi 简化/消除、规范化/GVN/DCE/CFG、内联、LICM、归纳变量、小循环展开、强度削弱和 PassManager 原样复用。
- 复用活跃性、区间分配、spill 槽和帧范围/冲突检查算法；将寄存器池和参数布局替换为 ARM 目标约束。
- 复用全局对象布局、按类型寻址和后端消费已分配 LIR 的设计，重新实现 ARMv8-A 指令选择、帧链、访存、分支及调用。
- 测试器改用 AArch64 GCC/QEMU，并实际执行 ARM 程序。原 RISC-V 文档和结果保存在 `docs/reference-riscv/`，不将其作为 ARM 成绩。

复制前补充了共享 LowerHIR 的必要死块清理：前端仍检查 return/break/continue 后的语义错误，但不可达声明不能保留无用的大入口 alloca。原 RISC-V 版本同步复验通过。该项不属于新性能优化。

本轮逐文件比较：73个src/include文件中68个与当前RISC-V项目逐字节相同；变化限定于main入口、位置分配的目标约束，以及ARM后端/ABI三个新文件。完整差异与来源指纹见SOURCE_MANIFEST.json。

## AAPCS64 实现

| 项目 | 实际处理 |
|---|---|
| 普通整数/指针参数 | 独立使用 w0–w7 / x0–x7，耗尽后按8字节槽入栈 |
| 单/双精度参数 | 独立使用 s0–s7 / d0–d7，FP寄存器耗尽后入栈；不会套用 RISC-V 的浮点转 GPR 规则 |
| Linux 变参 | 前端将float提升为double；未命名浮点仍使用 FP 参数寄存器/栈，整数与指针使用独立 GPR 参数计数 |
| 返回值 | i32用w0，指针用x0，float用s0，内部double用d0；Tensor内部接口延续形状参数和堆描述符指针 |
| 持久寄存器 | O1分配x19–x28、v8–v15；按ABI保存/恢复全部使用的GPR和FP寄存器低64位。x18保留给平台，不参与分配 |
| 临时寄存器 | 选择x9–x17与v16/v17；不与持久值、参数银行重叠 |
| 帧链 | x29指向保存的上一帧x29及x30；记录写完后才更新x29；恢复时回到记录位置并用ldp恢复与释放 |
| 栈布局 | SP保持16字节对齐；既有显式布局相对入口SP，FP访问转换偏移+16；输入栈参数位于FP+16，输出参数位于当前SP |
| 大偏移/常量 | movz/movk构造常量；超访存立即数范围时显式形成地址，保留独立地址临时寄存器 |
| 全局地址 | adrp + :lo12:，按页相对寻址；补充超过4GiB链接地址的实际执行。ARM没有照搬RISC-V的medany命名要求 |
| 整数与浮点 | i32的W寄存器算术，指针X寄存器；sdiv/msub实现余数；IEEE标量FP和截断转换；NaN有序/无序比较分别处理；窄整数比较解释实际位宽 |
| 条件分支 | 先跳到近距离局部标签，再无条件跳到目标块，避免把长CFG直接放入条件分支的短距离编码 |

参考 [Arm AAPCS64 官方规范](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst) 的 Linux 基本约定；仅参考规则，没有复制其编译器实现。当前只生成基础 ARMv8-A 标量指令；没有NEON向量化、专用指令调度或复杂窥孔优化。

## ARM 官方数据与测试可信度

独立下载了 `2026决赛arm赛道测试用例.tar.gz`，组织方版本 `c84d735436a0e1fc1af5091713ecb2b8f58bc4d9`，SHA-256 `38d189680ec711c50203c049e8b7e7557506f815783e36c0f456cb18fd1eb23a`。其中534个普通文件已经逐文件导入与哈希记录；相对继承的RISC-V测试有96文件内容不同。来源及完整文件清单见 `ARM_OFFICIAL_TEST_SOURCE.json`。

功能集由functional100例和h_functional50例组成；性能集60例。参考运行库为组织方compiler2022版本的原始sylib.c/h，交叉编译成ARM库用于第二套链接验证，源码与来源在 `tests/reference-runtime/`。该库不冒充目标板确切版本。

测试器读取同名.in/.out，分别检查编译、链接、执行状态，并比较stdout和8位退出码。信号、超时、缺oracle不算通过；LLVM18文本解析只作为附加验证。历史故障注入脚本已迁移到ARM并重跑。

`test_arm64_abi.py` 额外检查20个浮点变参、混合变参、1000个整数/浮点参数（栈偏移超过4KiB）、40个混合参数的GCC双向调用，以及全部x19–x28和d8–d15的保存。O1互操作检查显式关闭内联，只保留Mem2Reg和实际寄存器分配，防止内联把需要核验的外部调用消掉。独立汇编驱动种下寄存器值后检查，未仅依赖自己的布局Verifier。

## 局限与后续

1. 保留当前公开用例范围的Tensor语义，仍没有独立完整Tensor规范；普通数组形参只有地址ABI，整体Tensor运算需要携带形状的Tensor参数。
2. 沿用现有单对象/帧的int32范围保护；64位指针不表示已支持在4GiB物理内存中分配任意大小单一对象。
3. 大型性能用例的QEMU耗时不等于目标板时间；超时结果单独保留，不能把编译链接成功记为输出正确。本轮不针对具体用例添加优化或特殊分支。
4. 宿主Sanitizer检查编译器自身；目标代码使用交叉链接、真实QEMU执行与独立C参考检验。
5. 静态分析有已分类告警：新后端两条是比较条件初值随后被完整switch覆盖；继承Tensor代码两条为跨翻译单元未识别report_error抛异常的路径，另有内部null AST健壮性风险。没有据此宣称发现三个源程序崩溃，也不声称零告警。
6. 官方平台记录、实际硬件性能、队员理解与完整原始来源历史仍需参赛队完成；本地回归不替代这些要求。

最终计数、二进制与源码指纹、完整命令及未完成项见 `ARM64_VALIDATION.json`；包哈希与独立解包重建结果见 `dist/BUILD_INFO.json`。
